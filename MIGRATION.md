# Migrating `SG_final_round/` into the repository layout

The sleep experiments (explicit QIR `sleep` between X-memory extraction rounds, on H2-1E / H2-2E and on
physical H2-1 / H2-2) live in `SG_final_round/` as a self-contained folder of loose scripts. This file is
the plan for moving them into the structure of the rest of the repo, in eight stages. Stage 0 wrote this
file and `.gitattributes`, and changed nothing else.

Written from a full read of: `README.md`, `REPRODUCE.md`, `pyproject.toml`, `.gitignore`,
`hardware/README.md`, `hardware/*.sh`, `run_*.sh`, `notebooks/_build.py` (skimmed), the layout of
`src/qec_timing/` and `tests/`; and in `SG_final_round/`: `README.md`, `AGENTS.md`, `env/README.md`,
`configs/`, all 72 files in `src/` and all 4 in `tests/`. The decisions are in §6.

## 1. Ground rules

- Measured data never changes. Everything under SG_final_round/programs, runs, results, outputs is moved with `git mv`, never edited, except fixing relative links in .md files. Absolute /Users/harshank_s/... paths inside historical JSON stay as they are.
- Never submit, check or fetch jobs: no aqora/qnexus calls, no build-script actions check/execute/fetch-*, no --confirm.
- Do not change the contents of any CONFIG dict or any QIR-generating code: build folder names are a hash of CONFIG + QIR text.
- Keep the physical H2-2 decoder policies in SG_final_round/AGENTS.md exactly. Never pool the two d=5 mappings (original, skip-index-5).
- This machine is Windows: no clang and no H2 env. Verify programs by regenerating the .ll text and comparing it with the committed .ll. Skip anything needing guppylang 0.21, hugr-qir or aqora and say so.
- Run Python with .venv\Scripts\python.exe.
- Every file the package writes is written with `newline='\n'` and `encoding='utf-8'` (Windows defaults are CRLF and cp1252; see S2).
- Comparisons against committed results: integers (counts, shots) exact; decoded rates rel tol 1e-9; fitted parameters rel tol 1e-4; text compared after normalising line endings; figures and PDFs are not regression targets (S3).
- Any reproduce run skips `.venv/` when snapshotting `git status`.
- Stop at the end of each stage, summarise what changed, and do not commit.

Removed at the end: `SG_final_round/` (including its `.gitignore`, `results/.gitkeep` and the duplicate PDF)
and `output/` (everything in it moves to `results/sleep/`).

**Writing rule.** The package never overwrites an existing file in `results/sleep/programs/`,
`results/sleep/runs/` or `config/sleep/`. New experiments may add new files there. Per-run analyses that the
original scripts wrote into `runs/` or `programs/` (DEMs, `analysis*.json`, `raw_analysis.json`, `.npz`,
manifest updates) are written to `store/sleep/` instead, and tests compare them with the committed copies.
Top-level reports go to `results/sleep/` and figures to `results/sleep/figures/`, so `git diff` after a rerun
is the regression check, as in the rest of the repo.

Proposed modules in `src/qec_timing/sleep/` (the brief's list, plus `qir.py`, `unpack.py`, `jobs.py`,

### Facts that constrain the migration

1. **Build folder names.** Reproducible from CONFIG + QIR text: `d3_sleep_sweep_f219bffeea86811d`,
   `d3_sleep_five_point_a2588f7078f6e696`, `d3_sleep_five_point_h2_2e_67d11d0348065703`,
   `d3_fixed_sleep_690baca08b24dfd2`, `d3_fixed_sleep_refinement_3bb6e107a0ff6de3`,
   `d3_fixed_sleep_resolution_c2380924e8c69578`, `d5_fixed_sleep_9fb82150bc37143a`; from QIR text only:
   `single_qubit_2c64d96fea4bbbac`, `single_qubit_sweep_73005efe45e835e4`. `OPTIONS` (from
   `single_qubit_sweep.py`) is part of the d3 CONFIGs, so it must stay the same dict. Fixed names (no hash):
   the zero-sleep, half-second and skip5 folders. **Probe folders:** `build_sleep_probe.py` hashes the
   folder's config plus the *builder file's own bytes*. The committed builder is `8f1775a2...` (LF bytes), the
   `builder_sha256` recorded in `5944c048c1dfdc80` and `8cca8353b3f06d18`, so both names **reproduce**
   (verified in stage 1, each from its own `config.json`). Only `98ff453353750ae5` can't be rebuilt: it came
   from an older builder (`ecaf8610...`) and an older single-duration config format; its `.ll` text still
   matches. (An earlier draft of this fact quoted `f65cf22b...` as the current builder: that was the hash of
   the CRLF working copy before stage 1 restored it.) How stage 3 keeps the two names reproducible: S1.
2. **Line endings.** `core.autocrlf=true`. Before `.gitattributes` existed, git converted the line endings
   of every file it took for text when checking them out. Now `.gitattributes` marks `results/**`,
   `config/**`, `output/**`, `SG_final_round/**`, `*.ll` and `*.dem` as `-text`.
   - **1,417 tracked files** with that attribute still have CRLF working copies; the committed blobs are LF.
     By folder: 587 `SG_final_round/runs`, 295 `programs`, 289 `results`, 72 `src`, 13 `configs`,
     111 `results/hardware`, 10 `output/hardware_budget`, 15 other `results/`. By type: 800 json, 208 ll,
     207 dem, 93 py, 54 md and others.
   - **Two PDFs are corrupted in this working tree** by that conversion:
     `SG_final_round/results/d3_h2_1e_full_methodology_all_shots.pdf` and `sleep_parameter_explanation.pdf`.
   - The 9 `.sh` files (`eol=lf`) are also CRLF on disk.
   - `git status` still shows them as clean only because of the index stat cache.
   - The fix is to restore those working copies from the index (stage 1, step 0), never `git add
     --renormalize`, which would commit the CRLF bytes.
   - Until then, the README's DEM hash check fails here (`56499613...` against the recorded `412d8dbd...`).
     Raw `result_0.txt` files have no newlines and verify fine.
   - The package reads text with `read_text()` and writes with `newline="\n"`.
3. **Scripts write into measured-data folders and outside the folder.** Some analyses write `.dem` files and
   `manifest.json` into `programs/<build>/` and analysis files into `runs/`. Builders rewrite
   `configs/*.json`. Three plot/PDF scripts write to the repo-level `output/pdf/`. The writing rule (§2)
   replaces all of this.
4. **Recorded paths are re-opened.** 609 files hold `/Users/harshank_s/...` (440 under `runs/`, 116
   `programs/`, 51 `results/`, 2 `configs/`). Analyses open `job['program']`, `item['path']` (in
   `d5_h2_1e_all_job_status.json`), `source['run']` (in `d3_fixed_sleep_all_shots.json`), `row['raw_path']`
   and `row['dem_path']`. Some `job.json` `program` fields are relative (`SG_final_round/programs/...`) and
   one is absolute. The `hardware_budget` JSONs hold `SG_final_round/runs/...`. All of these are resolved by
   `paths.recorded()`; the files stay as they are.
5. **Policy dicts are compared for equality.** `analyze_d5_h2_2_t1_20261113` asserts
   `job['decoder_policy'] == config JSON`, and `fit_h2_2_g1` asserts `data['decoder_policy'] == POLICY`.
   So the three decoder JSONs must stay byte-for-byte as they are, including the absolute
   `calibration_result` path in `h2_2_d5_skip5_decoder.json`.
6. **`exec()` across files.** `combine_h2_2_updated_decoder.py` and `test_h2_2_decoder_sensitivity.py`
   `exec` `unpack_hardware` out of `runs/h2_2_hardware_d3_x_t1_20261111/analyze.py`.
   `create_combined_sleep_pdf.py` `exec`s the top half of `create_h2_2e_summary_pdf.py`. The package copies
   or imports instead.
7. **Inputs with no generating script** (only committed outputs, so they act as fixed inputs). These are
   listed in `results/sleep/README.md` under "Fixed inputs (no generating script)":
   - inputs to four fits: `d3_d5_all_explicit_sleep_logical_comparison.json`, `zero_sleep_pooled_d3_d5.json`;
   - other inputs read by scripts: `d5_h2_1e_all_job_status.json`, `d5_h2_2_skip5_t1_p_ext_0_005_2000_shots.json`,
     `d5_h2_2_zero_sleep_pooled_750.json`, `d5_fixed_baseline_before_sleep_redecode_d5d743d35114.json`,
     `circuit_audit/all_stabilizer_syndrome_comparison.json`;
   - results nothing reads: `h2_2_hardware_p_ext_0_00117_all_shots.*`, `d3_d5_calibrated_g_one_third_fit.json`,
     `d3_n2_logical_quadratic_fit.json`, `d3_d5_u1_per_qubit_readout_errors.json`,
     `d3_sleep_five_point_emulator_comparison.json`, `d3/d5_zero_sleep_repeat_comparison.json`,
     `zero_sleep_extraction_controls.json`, `zero_sleep_d3_d5_physical_extraction_comparison.json`,
     `hqc_since_renewal_20261105.json`, `physical_hqc_audit_20261115.*`, `single_qubit_local_validation.json`,
     `sleep_sweep_H2-1e-2e_d_3_results.pdf`, most `*_submission.md` and status files;
   - figures `d3_fixed_sleep_preliminary.*` and `d5_h2_1e_completed_sleep_probabilities.png`.

   The runs `d3_zero_sleep_n2_1000_repeat_20261106`, `d5_zero_sleep_n2_1000_repeat_20261106` and
   `d5_fixed_sleep_additional_20261106_500_n4_5_6_7` have no committed submit script.
8. **Environment.** There is no `.venv` in this checkout. Python 3.11, 3.12 (uv) and 3.14 are installed;
   clang is not. Analyses need numpy, scipy, stim, pymatching and matplotlib. Reports also need reportlab,
   pypdf, pypdfium2 and PyMuPDF, and `create_*_pdf` need macOS system fonts (`/System/Library/Fonts`).

## 6. Decisions

- **Q1 `.venv`.** Python 3.12. Use the versions pinned in `envs/main.txt`, but install them one package at
  a time so one failure doesn't stop the rest. Skip guppylang, selene, hugr and pytket if they don't
  install on Windows, and record what was skipped in `..\sleep_baseline\env.txt`.
- **Q2 `env/`** → `results/sleep/env/`.
- **Q3** Drop `SG_final_round/.gitignore`; the root `.gitignore` already ignores `.venv*/`.
- **Q4** `output/` is entirely Harshank's sleep work: `output/hardware_budget` → `results/sleep/hardware_budget/`
  and `output/pdf/*.png` → `results/sleep/figures/`, with their paths fixed.
- **Q5** Figures and PDFs made by the package go to `results/sleep/figures/`. Keep
  `results/sleep/d3_d5_g1_stacked_fits.pdf` and drop its byte-identical copy from `outputs/` (noted for the
  PR description, §7).
  **Writing rule:** the package never overwrites existing files in `results/sleep/programs`,
  `results/sleep/runs` or `config/sleep`. New experiments may add new files there. Regenerated per-run
  analyses that used to be written into `runs/` or `programs/` go to `store/sleep/` (gitignored, like the
  rest of `store/`), and tests compare them with the committed copies. Top-level reports are written to
  `results/sleep/`, so `git diff` after a rerun is the regression check, as in the rest of the repo.
- **Q6** `.gitattributes` created in stage 0 (hashed artifacts `-text`, `*.bc *.npz *.pdf *.png binary`,
  `*.sh text eol=lf`). Working copies are restored in stage 1, step 0 (fact 2).
- **Q7** No separate `DECODER_POLICY.md`. The policy goes in a root `AGENTS.md`: the text of
